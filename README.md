# StoryApiMod — базовые сюжетные триггеры

Minecraft 1.21.1, NeoForge 21.1.224, Java 21.

## Где писать сюжет

`src/main/java/com/thestone/storyapimod/story/StoryTriggerExamples.java` — уже подключённые примеры. Заменяйте условия, координаты и действия здесь. Регистрация выполняется при запуске сервера, в том числе встроенного сервера одиночной игры.

- `onBlock(id, once, condition, action)` — ПКМ по блоку. Условие и действие получают `ServerPlayer` и `BlockPos`. Проверяйте измерение вместе с координатами. Тип блока можно проверить через `player.level().getBlockState(pos).is(Blocks.CHEST)`.
- `onEntity(id, once, condition, action)` — ПКМ по сущности. Условие и действие получают `ServerPlayer` и `Entity`. В примере используется житель с тегом `story_guide`; можно фильтровать по типу, UUID или тегу.
- `onEnter(id, dimension, bounds, once, action)` — вход в прямоугольную область `AABB`. Действие получает игрока.

Каждый `id` должен быть уникальным среди всех трёх типов. `once = true` означает один раз для каждого игрока, с сохранением в существующем attachment `COMPLETED` после выхода и смерти. `false` разрешает повторения. Чтобы проверить выполнение другого шага, используйте `triggers.isCompleted(player, id)` внутри условия блока или сущности.

Действия — обычный Java-код: сообщение, выдача предмета, телепортация и т. п. Одноразовое событие отмечается выполненным перед вызовом действия; если действие выбросит исключение, отметка останется. Регистрация и вызовы API рассчитаны на серверный поток.

## Поведение

ПКМ обрабатывается через `RightClickBlock` и `EntityInteractSpecific`, только на сервере и только для основной руки. Это событие попытки взаимодействия, а не подтверждение успешной торговли/использования предмета. Стандартное взаимодействие не отменяется: сундук открывается, с жителем можно торговать. Удержание ПКМ может повторять триггер с `once = false`. Режим наблюдателя исключён.

Области проверяются каждый серверный тик по положению ног игрока. Нижняя граница включена, верхняя исключена. Внутри области событие не повторяется; для повторения нужно выйти и войти. Появление внутри области после входа на сервер, возрождения или телепортации считается входом. Область учитывает измерение; быстрое пересечение всей области между двумя проверками не обнаруживается. Временные данные присутствия очищаются при выходе игрока и остановке сервера.

## Проверка в игре

Используйте тестовый мир с разрешёнными командами. Примеры включены по умолчанию.

1. В обычном мире поставьте блок командой `/setblock 0 64 0 minecraft:stone` и нажмите по нему ПКМ. Появится «Вы нашли сюжетный блок!». Повторный ПКМ не должен выводить сообщение.
2. Создайте проводника: `/summon minecraft:villager ~ ~ ~ {Tags:["story_guide"]}`. ПКМ по нему выведет реплику один раз. Обычный житель без тега её не вызывает.
3. Войдите в область `10 <= X < 20`, `60 <= Y < 80`, `10 <= Z < 20` в обычном мире. Например, в творческом режиме используйте `/tp @s 15 70 15`. Появится сообщение о входе. Стояние внутри не должно повторять сообщение. Выйдите через `/tp @s 25 70 15` и вернитесь — сообщение появится снова.
4. Перезайдите и проверьте блок/жителя: одноразовые реплики не должны повториться. Повторите после смерти. У второго игрока события должны выполняться независимо.
5. Проверьте такие же координаты в другом измерении: примеры блока и области там не срабатывают.

Для повторного тестирования одноразового события можно временно изменить его `id` или использовать новый мир/игрока. Изменения Java-кода требуют пересборки и перезапуска игры.
