# Новые триггеры, WAIT и диалоги

Главный класс мода и ModKeymappings не меняются. Регистрация дополнительных обработчиков выполняется через EventBusSubscriber. Старые JSON версии 1, поля dialogue, onStart и onComplete продолжают работать.

## Ожидание суток перед следующим разговором

Полный пример: src/main/resources/story_examples/wait_for_guide.json. Его можно скопировать в config/storyapimod/stories и выполнить /story reload. Этот дополнительный пример не устанавливается автоматически. Он использует жителя с тегом story_guide; при тесте рядом с village.json оба сюжета могут реагировать на одного жителя. Для отдельного теста оставьте в папке только нужный сюжет или измените тег NPC.

У завершаемого квеста:
```json
"completionActions": [
  { "type": "wait", "ticks": 24000 },
  { "type": "complete_event", "event": "storyapimod:guide_ready" }
]
```

У следующего квеста:
```json
"start": {
  "type": "entity_click",
  "entity": "minecraft:villager",
  "tag": "story_guide",
  "requires": "storyapimod:guide_ready"
}
```

Квест завершается и выдаёт награду сразу. Его completionActions блокируют дальнейшее прохождение этой сюжетной цепочки. После ожидания игрок должен снова нажать ПКМ по NPC: ранний клик не сохраняется. Другие сюжетные цепочки и другие игроки продолжают работать.

24000 серверных тиков — один цикл суток при обычном ходе времени, примерно 20 минут при 20 TPS. Сон, /time set и /time add не ускоряют WAIT. Пока игрок офлайн, мёртв или в режиме наблюдателя, очередь стоит на паузе. Остаток ожидания, счётчики и события сохраняются в данных игрока, переживают обычный перезапуск сервера и смерть.

## Действия и задержки

Необязательные списки:
- startActions — после начала квеста.
- actions — после завершения отдельной цели.
- completionActions — после завершения всего квеста.

Действия исполняются по порядку. Поддерживаются wait (также WAIT), dialogue и complete_event. Диалог запускается без автоматического ожидания его окончания. Если нужна пауза до следующего действия, укажите wait явно:
```json
"actions": [
  { "type": "dialogue", "text": "Подожди здесь.", "duration": 100 },
  { "type": "wait", "ticks": 100 },
  { "type": "dialogue", "text": "Теперь можно идти.", "duration": 80 }
]
```

duration и ticks задаются в тиках. dialogue.duration по умолчанию 100 (допустимо 30..12000). wait.ticks: 1..24000000. Действия dialogue добавляются в прежнюю клиентскую очередь, поэтому уже отображаемые реплики могут отложить их фактическое отображение.

У любого trigger можно указать delay — минимальное количество активных серверных тиков перед приёмом события, и requires — ID уже завершённого события. Пример: {"type":"entity_click","entity":"minecraft:villager","delay":100}. События, случившиеся до конца задержки, не засчитываются. Для суток после предыдущего квеста используйте completionActions с WAIT, а не delay у разговора.

После /story reload активные последовательности сохранённых квестов продолжают выполняться по уже сохранённому списку действий. Новые прохождения используют обновлённый JSON. Очереди удалённых квестов отменяются при перезагрузке для онлайн-игроков, для остальных — при входе.

/quest reset <quest> [player] отменяет очереди, задержки, счётчики и созданные этим квестом события только выбранного игрока. Прогресс других квестов автоматически не откатывается; для повторного тестирования всей цепочки сбросьте каждый её квест.

## Триггеры

Каждый пример ниже — содержимое поля trigger либо start. dimension по умолчанию minecraft:overworld. Для других измерений указывайте его явно. tag — scoreboard-тег сущности, а не registry-тег.

| Тип | Дополнительные поля / пример |
| --- | --- |
| entity_killed | entity: minecraft:zombie, count: 3; необязательный tag |
| item_picked_up | item: minecraft:apple, count: 5 |
| item_crafted | item: minecraft:stick, count: 8 |
| block_broken | block: minecraft:stone, count: 10 |
| item_used | item: minecraft:apple, phase: finish, count: 1 |
| dimension_changed | dimension: minecraft:the_nether, from: minecraft:overworld (from необязателен) |
| night_started | Переход через начало ночного интервала 13000..22999; в измерениях с обычной сменой дня и ночи |
| inventory_contains | item: minecraft:emerald, count: 3 |
| health_below | health: 6 (строго меньше 6 единиц = 3 сердец; поглощение не считается здоровьем) |
| sleep_started | Успешное засыпание; не просто нажатие на кровать |
| sleep_ended | Пробуждение, включая ручной выход из кровати |
| area_exit | min: [10,-61,10], max: [20,-50,20] |
| look_at | block: minecraft:chest ИЛИ entity: minecraft:villager; distance: 6; необязательный tag |
| npc_distance | entity: minecraft:villager, tag: story_guide, distance: 4 |
| event_completed | event: storyapimod:guide_ready |

Существующие block_click, entity_click и area_enter сохранены. Тип блока и предмета проверяется по registry ID, компоненты/NBT предмета не сравниваются.

count по умолчанию 1. У убийства, подбора, крафта, использования и разрушения количество накапливается только для активной цели (или активного условия начала). При подборе учитывается фактически принятая часть стопки. Убийство засчитывается игроку — источнику смертельного урона, в том числе его снаряду; убийства питомцем не засчитываются. Крафт означает изготовление через событие ItemCraftedEvent, не переплавку в печи.

inventory_contains проверяет суммарное количество в обычных слотах, броне и второй руке; предметы не забираются. Открытый контейнер, курсор и содержимое вложенных сумок не учитываются. Наличие предметов и низкое здоровье могут удовлетворить цель сразу после её активации. После завершения цели она повторно не запускается.

item_used.phase:
- finish (по умолчанию): завершение длительного использования, например съеденное яблоко или выпитое зелье.
- start: начало длительного использования.
- release: прекращение использования, например отпускание лука; не гарантирует успешный выстрел.
- click: неотменённое событие ПКМ предметом в воздух; это попытка использования, а не гарантия эффекта предмета.

Взгляд проверяется серверным лучом от глаз, стены и ближайшие доступные для выбора сущности перекрывают цель. distance ограничено 128 блоками, по умолчанию 6. npc_distance измеряется от позиции игрока до позиции подходящей сущности; видимость для него не требуется. Проверяются только загруженные сущности.

area_exit требует сначала находиться внутри области при активной цели, затем выйти из неё в том же измерении. Вход в мир снаружи, смена измерения и выход с сервера не считаются выходом из области. night_started требует наблюдаемого перехода из дня в ночь; вход ночью сам по себе не засчитывается.

event_completed и requires принимают ID завершённого квеста, шага или события, созданного действием complete_event. Используйте уникальные ID шагов/событий во всех сюжетах. Ссылки на неизвестные ID отклоняются загрузчиком. Не создавайте циклические зависимости и не требуйте от начала квеста событие, которое может создать только этот же квест.

## Внешний вид диалогов

Изменён только render в DialogueSubtitles: ванильная чёрная подложка с прозрачностью из настроек, текст с тенью и потемнением от белого к серому. Цветовые и шрифтовые стили сообщений визуально не применяются, чтобы вид соответствовал ванильным субтитрам. Сами компоненты и сетевой формат сохранены.

Позиция (центр экрана, прежняя высота), длительности, плавное появление/исчезновение, очередь, пауза и callbacks не изменены. Направляющие стрелки звука не добавлены: у сюжетной реплики нет источника звука.

## Проверки

StoryFilesTest проверяет прежний JSON, пример ожидания суток, ссылки на события и ошибки загрузки. StoryExecutionTest проверяет очередь, ожидание 24000 тиков, сохранение/загрузку, независимость состояний игроков, сброс, счётчики и новые типы JSON. Задачи storyParserTest и storyExecutionTest подключены к check, поэтому выполняются при build. Для них добавлена только тестовая зависимость Gson.

В игре стоит проверить частичный подбор при почти полном инвентаре, крафт с Shift, отменённое разрушение защищённого блока, сон, перезаход посреди WAIT и двух игроков на разных этапах. Для быстрого теста замените 24000 на 100 в своём тестовом JSON.
